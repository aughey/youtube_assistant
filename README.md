# youtube_assistant

Watches a directory for video files, transcribes each video locally, generates YouTube metadata through an OpenAI-compatible chat endpoint, and uploads the video to YouTube.

The pipeline is resumable. For `example.mp4`, the app creates these sidecar files:

- `example.txt`: Whisper transcript.
- `example.metadata.json`: generated title and description.
- `example.uploaded.json`: YouTube video id, URL, and upload details.
- `example.upload-dry-run.json`: written instead of `example.uploaded.json` when `--no-upload` is set.

On startup the app always scans the watch directory and runs only missing stages. While running, it watches for newly created or modified video files.

## Google setup

1. In Google Cloud Console, create or choose a project.
2. Enable the YouTube Data API v3.
3. Configure the OAuth consent screen.
4. Create an OAuth client for a desktop app.
5. Download the client secret JSON and keep it outside git, for example `client_secret.json`.

The app requests the YouTube upload scope through the generated Google client. On first run it opens the installed-app OAuth flow and writes refresh tokens to `.youtube_token_cache.json` unless `--token-cache` is set.

## Whisper

Start Whisper yourself before running the app. The app checks the configured Whisper URL on startup and exits with a suggested Docker command if the server is not reachable.

Default settings:

- Image: `hwdsl2/whisper-server:latest`
- Container name: `youtube-assistant-whisper`
- URL: `http://127.0.0.1:9000`
- Endpoint used: `POST /v1/audio/transcriptions`

Example:

```bash
docker run --rm --name youtube-assistant-whisper \
  -p 127.0.0.1:9000:9000/tcp \
  -e WHISPER_API_KEY=local-whisper-key \
  hwdsl2/whisper-server:latest
```

The container exposes an OpenAI-compatible transcription endpoint, as documented by [hwdsl2/whisper-server](https://hub.docker.com/r/hwdsl2/whisper-server). If `WHISPER_API_KEY` is set or auto-generated by a persistent install, run the app with `--whisper-api-key ...`.

## Run

```bash
cargo run -- \
  --watch-dir /path/to/incoming/videos \
  --client-secret /path/to/client_secret.json \
  --openai-base-url http://127.0.0.1:11434/v1 \
  --openai-api-key local-key \
  --openai-model your-chat-model
```

Useful options:

```bash
--privacy private
--category-id 22
--stable-seconds 5
--whisper-base-url http://127.0.0.1:9000
--whisper-model large-v3-turbo
--whisper-api-key local-whisper-key
--whisper-image hwdsl2/whisper-server:latest
--no-upload
```

Most flags also have `YOUTUBE_ASSISTANT_...` environment variable equivalents. Run `cargo run -- --help` for the full list.

Supported extensions: `.mp4`, `.mov`, `.m4v`, `.mkv`, `.webm`, `.avi`.

## Tracing

The app logs through `tracing-subscriber` and reads `RUST_LOG`. By default it emits `info` logs for `youtube_assistant`.

Examples:

```bash
RUST_LOG=youtube_assistant=debug cargo run -- ...
RUST_LOG=youtube_assistant=trace cargo run -- ...
```

## Notes

Uploads default to `private`. Use `--no-upload` to run transcription and metadata generation without contacting YouTube; this does not create `*.uploaded.json`, so a later normal run can still upload the video. The watcher waits for a video file's size to remain unchanged across several polls before starting work, which helps avoid processing a file while it is still being copied into the directory.
